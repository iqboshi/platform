# v6 Release Notes

## Focus

`v6` moves the platform workflow system further toward strict, composable semantics instead of convenience-first coupling.

## Included Changes

- Enforced the semantic split between asset handles such as `dataset_version` and loaded workflow data such as `table`, `geo_raster`, `image_collection`, and `feature_collection`.
- Expanded structured workflow composition with nested subgraph interfaces, scoped boundary nodes, and real `control.for_each` execution semantics across frontend analysis, backend validation, and runtime.
- Tightened starter handoff behavior so attachment stays metadata-driven, supports explicit target-node routing, and refuses ambiguous binds instead of mutating arbitrary nodes.
- Added and documented the shared versioned HTTP boundary contract for `provider_http_api` workflow nodes in `docs/architecture/custom-api-node-contract.md`.
- Updated workflow validation and frontend contract analysis so localization does not mutate machine-readable semantic tokens.
- Brought release and governance docs forward so GitHub pushes now require an explicit documentation freshness check.

## Validation

- `python .\scripts\validate_workflow_nodes.py`
- `python .\scripts\validate_docs.py`
- `npm run test --workspace @platform/web`
- `npm run build --workspace @platform/web`

## Follow-Up

- Lint and full backend test execution should remain part of the standard release checklist when time permits, especially after larger runtime changes.
- Future releases should keep the custom API transport contract and workflow node extension standard synchronized whenever boundary-node behavior changes.
